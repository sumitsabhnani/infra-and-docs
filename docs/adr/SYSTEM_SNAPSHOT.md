# SYSTEM SNAPSHOT

High-density context for AI coding agents. Reflects the active state of the system. For deeper rationale, see the numbered ADRs in this directory.

---

## 1. Product Vision & Domain

An **institutional-grade personal portfolio management and wealth analytics platform**. It competes with high-end tools like Bloomberg Terminal and InvestingPro — **not** consumer apps (Robinhood, Mint). Priorities, in order:

1. **Accuracy** — every number the UI shows must be mathematically defensible.
2. **Rigorous financial math** — `BigDecimal` everywhere, historical FX preserved, AVCO as the single realized-gain algorithm, immutable transaction ledger as truth.
3. **Premium data density** — multi-currency, multi-broker, cross-exchange aggregation surfaced without horizontal bloat.

Users are sophisticated investors tracking global portfolios across brokers, currencies, and asset classes. "Correctness > Convenience" is non-negotiable.

## 2. Core Business Entities

- **User** — owner of everything; reporting currency is a user-level preference. Carries `subscription_tier` (`FREE | EARLY_ACCESS_TRIAL | PRO`, default 90-day `EARLY_ACCESS_TRIAL`), `trial_started_at`, and `trial_ends_at`; `effectiveTier(now)` resolves expired trials to `FREE` at read time (ADR-050).
- **Portfolio** — a broker account (SnapTrade-synced) or a manual container (`broker = 99`); has dynamic transaction-backed holdings. Carries nullable `converted_from_broker_sync_at` stamped on zero-data-loss linked-to-manual conversion (`POST /api/portfolios/{id}/convert-to-manual` or trial expiry) to gate subsequent CSV imports at UTC `LocalDate` granularity (ADR-050).
- **SnapTradeConnection / SnapTradeUser** — broker linkage; state = (`status`, `sync_phase`, `failure_reason`); async event-driven sync with polling. `failure_reason ∈ { UNSUPPORTED_BROKER, UNKNOWN }` is the structured signal the frontend reads to render category-specific copy ("Broker not supported …") instead of pattern-matching free-text `last_sync_error` (ADR-030). Because SnapTrade bills monthly per `SnaptradeUser`, `SnapTradeService` blocks `FREE` / expired-trial users before `ensureUser` runs and calls `deleteSnapTradeUser` + deletes `snaptrade_user` whenever a user drops to `0` connections (with 5xx/abandoned-popup retry via `AbandonedConnectionReaperJob`) (ADR-050).
- **Broker (broker_metadata)** — vetted-broker catalog. Active rows with non-null `snaptrade_slug` are the only brokers the UI can offer; `snaptrade_slug` matches SnapTrade's `referenceData.listAllBrokerages` catalog verbatim (uppercase, hyphenated — `INTERACTIVE-BROKERS-FLEX`, not `interactive_brokers`). Manual placeholder (`id=99`, slug NULL) is excluded from `GET /api/brokers`. Redis-backed `brokers` cache is cleared on every JVM start by `BrokerCacheStartupClearRunner` so deploy → migrate → restart is self-healing for slug fixes (ADR-030).
- **Transaction** — immutable ledger row; carries `raw_data` JSONB audit trail, `broker_fx_rate`, USD-normalized fields, and cached `normalized_reporting_*` projections. `TransactionType` = `BUY | SELL | DIVIDEND | TRANSFER | BONUS | SPLIT | MERGER_IN | MERGER_OUT | SPINOFF_IN | RIGHTS_IN` — the last six are per-account broker emissions retained for audit only; **`PortfolioReplayService` filters them out of the AVCO timeline** so the EODHD/BhavKosh `corporate_action_*` row is the sole authority for position math (ADR-029). CSV import refuses to write them at ingest (`RowStatus.CORPORATE_ACTION_DROPPED`); SnapTrade still writes them but they are inert under the replay filter.
- **Holding** — current position; references `security_master_id` (canonical), `acquired_listing_id`, nullable `override_market_data_symbol_id`, `broker_raw_ticker` (never overwritten), and nullable `broker_snapshot_quantity` (stamped on SnapTrade-to-Manual conversion per ADR-050). `HoldingDto` carries `securityMasterId` (effective canonical master via `getEffectiveId()`) for dismiss-review (`setMasterReviewDismissed` authorizes callers owning either a `Transaction` or a `Holding` on the master) and `reviewState` + `reviewActionHint` (including split-normalized `suggestedQuantity` and `suggestedTransactionDate`, deduplicated once per effective master across cross-exchange rows) for triage CTAs. `acquired_listing_id` is mutable post-creation only via the superuser-gated `POST /api/v1/admin/holdings/{id}/rebind` (`HoldingAdminController` → `TickerMappingApplier.rebindAcquiredListing`), which refuses cross-master swaps, re-points matching `transactions` in lock-step, conditionally clears the override, optionally fires `JitSecuritySetupService.onNewListingCreated` on the new listing, and publishes `HoldingRebindEvent` for portfolio-wide replay (ADR-045).
- **SecurityMaster / SecurityListing / MarketDataSymbol** — three-layer identity: *what it is* → *where it trades* → *how it's priced*. `canonical_master_id` self-FK handles deduplication. `reviewDismissed` boolean (DEFAULT FALSE) suppresses the Needs-Review shelf badge without altering any calculation (ADR-032); distinct from `Holding.excludedFromCalculations` which removes the position from all totals. `market_data_symbol.symbol_kind` (`SymbolKind` enum — `EQUITY | RIGHTS_ENTITLEMENT | REIT | BOND | ETF | UNKNOWN`) is the structured-classification surface populated by `SymbolKindClassifier` at every write site so `LatestPriceRefreshJob` skips categories (e.g. `RIGHTS_ENTITLEMENT`) via a column filter, never a SQL string LIKE (ADR-040, ADR-049). `market_data_symbol.backfill_status` (`PENDING | SUCCEEDED | FAILED | NO_DATA`, NULL when never attempted) is the responsive terminal verdict written by `EodhdHistoricalPriceBackfillJob` on every retry-exhaustion / non-retryable / empty-bars-no-prior-data exit — read by `PortfolioBackfillStatusService` to drop listings from `pendingListingIds` within one poll cycle instead of waiting on the 15-minute staleness fallback (ADR-041).
- **ManualAsset** — user-level static assets (cash, gold, real estate). **Owned by User, never by Portfolio.** Supports `monthly_increment` via a scheduled physical-apply job.
- **UserAssetExposures** — pre-computed per-user per-asset-class read model for the allocation widget.
- **UserAssetClassTargets** — policy-level allocation rules (target %, max drift %).
- **MarketDataPriceDaily / LatestMarketPrice / FxRate** — historical OHLCV (EODHD/BhavKosh/AMFI), latest prices fed by the 15-min `LatestPriceRefreshJob` via in-process `YahooFinanceClient` (`/v8/finance/spark?range=1d&interval=5m` in 20-symbol chunks across NSE/BSE and global exchanges, gated per listing by `MarketHours.isExchangeOpen`) plus EOD/NAV exchange-close writes (`MarketHours.eodAsOf` / `navAsOf`) and async Yahoo JIT (`MarketDataService.enqueueYahooJitFetch`) on cold cache+DB miss; historical FX (EODHD). `LatestMarketPriceRepository` enforces deterministic `DISTINCT ON (security_listing_id) ... ORDER BY security_listing_id, as_of DESC NULLS LAST, provider_id ASC` reads and cross-provider monotonic `as_of` writes (`WHERE NOT EXISTS` + `ON CONFLICT DO UPDATE WHERE EXCLUDED.as_of >= latest_market_price.as_of`), emitting `LatestPricesRefreshedEvent` only when `rows > 0`. Reads serve from the `latestPrices` Redis region (24h backstop, `@CachePut`-driven) or the `latest_market_price` DB row — never a synchronous provider call on a user thread (ADR-038, ADR-049).
- **CashFlow** — non-trade portfolio cash movement (`flow_type` ∈ `DEPOSIT | WITHDRAWAL | FEE | INTEREST | TAX | FX_CONVERSION | ADJUSTMENT`), keyed by `portfolio_id`, signed `amount` stored verbatim from the broker payload. Populated by `SnapTradeActivityMapper` for SnapTrade activities with no security listing **and by `CsvImportService` at commit** for CSV rows resolved to `RowStatus.CASH_FLOW`; both paths collapse the noisier broker vocabulary (`CONTRIBUTION`/`MANAGEMENT_FEE`/`WITHHOLDING`/`CONVERSION`/`FX`) into the canonical seven. CSV uses a separate `csv:cf:v1:` external-id hash and a within-batch dedup pass to short-circuit collisions on the partial unique index. **Write-only from analytics today** — exists for audit completeness and future cash-balance reconciliation. Synthetic external_ids stay on `broker_activity_log` only and never propagate to `cash_flows.external_id` (ADR-028).
- **BrokerActivityLog** — immutable raw-payload audit row for every SnapTrade `Activity`; `parsed_status` ∈ `PENDING | PARSED | UNMAPPED_TYPE | …` and `parsed_entity_type` ∈ `TRANSACTION | CASH_FLOW | CORPORATE_ACTION` is the polymorphic discriminator routing each row to its destination table. `POST /api/v1/admin/snaptrade/replay-unmapped` (superuser-gated, keyset-paginated, idempotent) re-runs the parser against UNMAPPED rows when parser coverage extends (ADR-028).
- **PortfolioPositionChange** — per-`(portfolio_id, security_master_id)` (`ON DELETE CASCADE`) SnapTrade position-transition tracker (`first_observed_at`, `last_changed_at`, `last_observed_quantity`, `syncs_since_change`, `last_sync_counted_at`). Updated by `SnapTradeHoldingsReconciler.persistHoldings` on live quantity changes and incremented by `SnapTradeService.markSyncCompleted` at most once per clean portfolio-wide sync cycle to gate `PortfolioReviewClassifier`'s `>= 7d` & `>= 2` clean-sync grace window (ADR-051).
- **SecurityListingRenameHistory** — append-only audit of ticker changes detected against a same-ISIN anchor, unique on `(canonical_master_id, old_ticker, new_ticker, exchange_code)`. Active writer: `ExchangeSymbolLoadJob` (`source = 'EXCHANGE_LOAD_JOB'`, minting new sibling listings without mutating `security_listing.ticker` in place). Never participates in resolution — read-side canonicalization flows through `security_master.canonical_master_id`, and `PortfolioReviewClassifier` reads it as a corroborating signal for `HIGH`-confidence rename-pair `Link` suggestions (ADR-019, ADR-040, ADR-049, ADR-051).
- **CorporateActionSplit** — keyed by canonical `security_master_id`; read-time multiplier (`factor = ratioNumerator / ratioDenominator`) applied in `RealizedGainCalculator.AvcoState.applySplit` during the AVCO walk. Covers stock splits (20:1, 1:10 reverse) and stock dividends (21:20) identically. Ingested by `CorporateActionSplitBackfillJob` via JIT event, weekly sweep, and superuser admin endpoints; inserting a split/bonus (plus `ApplicationReadyEvent` startup self-heal) re-queues active `BHAVKOSH` symbols to `backfill_status = 'PENDING'` for full-history refresh, and `DailyBarSplitAdjuster` (`core/util`) translates daily bars between provider storage, terminal chart basis, and scalar trade-date unadjusted closes (`GET /api/holdings/listings/{listingId}/historical-close`, `120 req/hr`) (ADR-014, ADR-051).
- **CorporateActionCashDividend** — declared cash-dividend events (EODHD `/api/div/{SYMBOL}`), keyed by canonical `security_master_id`, `(security_master_id, ex_date)` unique. **Reconciliation-only, never read by analytics.** All user-visible dividend totals (`HoldingDto.totalDividends*`, dashboard per-portfolio `totalDividendIncome{Lifetime,Ytd}`) derive exclusively from `transactions` rows of type `DIVIDEND` via `DividendAnalyticsService`, summing `normalized_reporting_amount` at historical FX. The events table feeds `DividendAnomalyService` only — an admin-gated `/anomalies` endpoint with a `minExpectedTotal` triage filter — to flag broker-feed gaps against company declarations. Ingested via JIT event, Sunday 04:30 UTC sweep, and superuser admin endpoints (ADR-017).
- **CorporateActionMerger / CorporateActionSpinoff** — declared cross-master events that drive basis transfer between `security_master_id`s at an exact ex_date UTC. Merger: `(from_master_id, to_master_id, ex_date, ratio_numerator/denominator, cash_per_share?, cash_basis_pct_override?)`, unique on `(from_master_id, ex_date)`. Spin-off: `(parent_master_id, child_master_id, ex_date, shares_per_parent, basis_allocation_pct)` — pct stays **nullable**; authoritative source is IRS Form 8937 entered via the superuser admin endpoint. Replay treats null pct as `SPINOFF_MISSING_BASIS` (skip transfer, parent retains 100% basis). Consumed exclusively by `PortfolioReplayService` at read time via `AvcoState.mergeFrom / applyCashBoot / splitOffFraction`; emit ephemeral `CorporateActionLedgerEntry` rows that surface on the History page as `synthetic=true` audit rows (never persisted). Merger ingest: EODHD `/api/fundamentals` is the only auto-path on `CorporateActionMergerBackfillJob`, and it is **gated off by default** (`app.jobs.corporate-actions-mergers.enabled=false`) — the production subscription tier returns HTTP 403. Manual entry via `recordManualMerger` is unaffected. Spin-off ingest: BhavKosh `DEMERGER` rows seed metadata via `CorporateActionSpinoffBackfillJob` (JIT listener on `HistoricalPriceBackfillCompletedEvent` + Sunday 05:30 UTC sweep, gated by `app.jobs.corporate-actions-spinoffs.enabled` — effective default `true`); both async paths iterate `MarketDataSymbolRepository`'s BhavKosh flat-projection views and resolve DEMERGER counterparties via `SecurityListingRepository.findIndianListingsByTickerWithMaster` — no JPA-entity lazy proxies cross the `@Async` boundary. `basis_allocation_pct` lands NULL on BhavKosh writes; admins curate via `CorporateActionSpinoffService.recordManualSpinoff` (idempotent on `(parent, child, ex_date)`, flips `source` to `MANUAL`) (ADR-018, ADR-024, ADR-043).
- **FeatureFlag** — per-environment runtime toggle row keyed on `flag_key VARCHAR(128)` PK; `is_enabled BOOLEAN` plus `activated_at TIMESTAMPTZ` set only on the false→true edge (Days Active = `now() - activated_at` is the retirement signal). Each environment writes to its own DB so flag state is naturally scoped without schema gymnastics. `FeatureFlagService.isEnabled(key)` is `@Cacheable("featureFlags", key="#flagKey")` and **fail-closed** — unknown keys, cache misses, and DB/Redis outages return `false`. Admin mutations at `/api/v1/admin/features` (superuser-gated) carry `@CacheEvict(value="featureFlags", allEntries=true)`; public `GET /api/v1/features` returns only enabled flag keys (disabled keys often name in-flight features and must not leak). Frontend `FeatureFlagService` (Angular) hydrates a `Set<string>` signal on app boot and after every admin toggle (ADR-037).
- **Queues** — `figi_resolution_queue`, `ticker_resolution_queue`, `global_ticker_mapping` (crowdsourced cache).
- **Copilot Chat Sessions** — LLM-assisted analysis surface (currency-normalized inputs required).

## 4. Strict Architectural Principles

- **Accounting Tie-Out Principle** — every row must sum to the summary header. Holdings rows and group summaries compute through the same `ValuationEngineService`; realized gain flows through a single `AvcoState` state-machine (`RealizedGainCalculator`).
- **History / Ledger View — Server-Authoritative, URL-Driven** — `/api/history/{summary,transactions,closed-positions,missing-transactions}` (ADR-013, ADR-051) replays the ledger once per request through the same `AvcoState` to emit raw txns, closed-episode rows (qty transition `>0 → 0`, with `episodeIndex` for re-opens), and data-issue rows unified via `PositionGapReconciliationStrategy` (`PortfolioReviewClassifier`, including `0`-transaction portfolios when `snaptrade_position_reconciliation` is enabled). Filter/tab/page state lives in URL query params.
- **Unified Valuation Engine** — all reporting-currency cost basis, gain/loss, and FX impact math lives in one place. Any new aggregator calls in; never re-implements.
- **Canonical Live-FX Path via `ExchangeRateService`** — all live-FX conversion routes through `ExchangeRateService.convert(amount, from, to)` / `getRate(from, to)` / `getRateWithInverseFallback(from, to)`. Sub-units (GBX = `0.01` GBP) are normalised inside `getConversionRateInternal` via a chain through the major currency — call sites never name the conversion factor and stay unaware of minor-unit complexity. Legacy parallel paths in `api` are retired: `CurrencyConversionService.convert(BigDecimal, String, String)` deleted (display helpers on the same class — `isGBX`, `convertGBXtoGBP`, `formatWithCurrency`, … — retained), `PortfolioValuationService.resolveGBPPrice` now delegates. Historical FX continues to flow through `HistoricalFxRateService` per ADR-011's fallback hierarchy. Adding a new minor unit (US cents, ZA cents, …) is a single-branch edit in `getConversionRateInternal` plus a constant; the `api` module never participates (ADR-044).
- **Immutable Ledger, Cached Projection** — `transactions` is truth and is never rewritten. Corporate actions (stock splits, stock dividends, mergers, spin-offs) live in `corporate_action_*` tables and are applied **at read time** inside `AvcoState` during the ledger replay — never back-adjusted into transaction rows (ADR-014, ADR-024). `normalized_reporting_*` columns are a rebuildable cache. Changing reporting currency or correcting a split invalidates the cache, never the ledger.
- **`corporate_action_*` Is the Only AVCO-Authoritative Source for Corporate Events** — broker-reported `Transaction` rows of types `BONUS, SPLIT, MERGER_IN, MERGER_OUT, SPINOFF_IN, RIGHTS_IN` are filtered out of `PortfolioReplayService`'s timeline (`BROKER_REPORTED_CORPORATE_ACTION_TYPES`). They remain in the ledger for audit but contribute zero to position math; the EODHD/BhavKosh-populated `corporate_action_*` tables are the sole moving force. CSV import refuses these rows at ingest (`RowStatus.CORPORATE_ACTION_DROPPED`); SnapTrade still writes them but they are inert under the replay filter. `HoldingService.persistHoldingFromReplay` reads `transaction.securityListing.security` directly — the resolver is not consulted at read time, eliminating the `AmbiguousIdentifierException` WARN cascade for ambiguous tickers (ADR-029). **User-initiated rights/free allotments must use `transactionType='BUY'` with `price=0`** — never `RIGHTS_IN`, which is silently dropped. BUY @ price=0 enters the AVCO walk correctly (cost basis=0, full proceeds become realized gain) and is the canonical form for this case (ADR-032).
- **Master Deduplication via Read-Time Canonicalization** — never modify transaction or holding rows to fix duplicate `security_master` entries. Set `security_master.canonical_master_id` on the loser; every aggregator resolves via `SecurityMaster.getEffectiveId()` / `COALESCE(canonical_master_id, id)` at read time. Ingestion dedup is best-effort (never throws), and the superuser `POST /api/admin/securities/link` endpoint is the manual counterpart to the async FIGI canonicalizer. **Ticker renames extend the same rule**: `ExchangeSymbolLoadJob` mints a new listing under the canonical master — never updates `security_listing.ticker` or flips `is_active` on the old row — and writes an audit row to `security_listing_rename_history`. Both old and new listings remain active under the same canonical master; CSV dedup hash idempotency (`CsvImportService.computeRowHash`) is preserved by construction (ADR-019, ADR-040, ADR-049).
- **Null-Exchange Listing Promotion at Write Time** — `SecurityListingService.findOrCreateByTickerOrFigiOrExchange` Step B' promotes an existing `exchange_id IS NULL` sibling rather than creating a duplicate when an exchange resolves late, gated on currency match + zero transactions on the candidate + exactly one match. Promotion re-fires `JitSecuritySetupService.onNewListingCreated` and re-enqueues FIGI because the original Phase α JIT bailed for the null-exchange row. Backed by partial index `idx_security_listing_ticker_null_exchange`. Composes with ADR-019: promotion eliminates the listing-level duplicate at write time; canonicalization is the master-level safety net when promotion's gates don't fire (ADR-028). The sibling write-time guard at Step C: when the caller supplied a broker `currency` AND Step B2 (`findByCurrencyIgnoreCase`) returned zero same-currency candidates, Step C (ticker-only fallback) is **skipped** and a new listing is created instead — reusing a known mismatched-currency listing was the ARCA-bound-to-XETRA bug. Step C still runs on bare-CSV imports (currency null, ADR-027) and on Step B2 multi-match (first-by-id legacy preserved) (ADR-045).
- **EODHD JIT Backfill Is Serial, Throttled, Bounded-Retry** — `EodhdHistoricalPriceBackfillJob.onBackfillRequested` runs on the dedicated single-threaded `eodhdHistoricalBackfillExecutor` (queue 1000, `CallerRunsPolicy`), with a 200ms pre-call throttle and a 3-attempt linear-backoff retry (1s → 2s) on `EodhdApiException` (network I/O, 5xx, transient rate-limit). `HistoricalPriceBackfillCompletedEvent` is the load-bearing trigger for `CorporateActionSplitBackfillJob` — transient upstream failure must not silently break the splits cascade. The shared `backgroundJobExecutor` must not be reintroduced for this listener. Pattern generalises: per-provider serial executors are the right home for any external-API JIT consumer that fan-outs a fragile event chain (ADR-028).
- **Latest-Price Read Path: Unified Yahoo Intraday Polling + Monotonic `latest_market_price`, No Sync HTTP on User Threads** — `GET /api/stocks/{id}/current`, `/figi/{id}/current`, and `/batch/current` serve from the `latestPrices` Spring cache (24h backstop, `@CachePut`-driven by `LatestPricesRefreshedEvent`) or the `latest_market_price` DB row — never a synchronous provider call on a user thread. Cold cache+DB miss enqueues an async JIT (`MarketDataService.enqueueYahooJitFetch`) on a bounded 2-thread `yahooJitExecutor`, deduplicated via `inFlightFetches` (`yahoo:{symbol}`, hard-capped at 1,000 entries) and throttled via the shared 1000ms `YahooFinanceRateLimiter`. `LatestPriceRefreshJob` (every 15 min, defaulting to `REFERENCED` scope) derives Yahoo tickers via `YahooSymbolDerivationService` while preserving canonical `market_data_symbol.provider_id` ownership, gates each listing via `MarketHours.isExchangeOpen` (exchange schedule + 30-min post-close buffer), batch-polls `GET /v8/finance/spark?range=1d&interval=5m` (20 symbols/chunk), normalizes sub-units (`"GBp" → "GBX"`, `"ZAc" × 0.01 → "ZAR"`, `"ILA" × 0.01 → "ILS"`), probes `/v8/finance/chart` when `/spark` omits currency on cold `LSE` or any `JSE` listing, and enforces cross-provider monotonic `as_of` ordering in `LatestMarketPriceRepository.upsertLatestPrice` so stale EOD/backfill bars (`MarketHours.eodAsOf` / `navAsOf`) never overwrite fresher intraday quotes or emit false `LatestPricesRefreshedEvent` cache updates (ADR-038, ADR-049).
- **Connected-Component Valuation Engine** — `PortfolioReplayService` walks each portfolio as a set of `ReplayChain`s (connected components of masters under merger + spin-off edges). Cross-master basis transfer fires at an exact ex_date UTC timestamp via `AvcoState.mergeFrom / applyCashBoot / splitOffFraction`; audit surfaces as ephemeral `CorporateActionLedgerEntry` rows on the History page (`synthetic=true`). The `transactions` table stays strictly append-only — no merger/spin-off row is ever written to it, and the `Transaction.TransactionType` enum is not extended. Single engine across `HistoryQueryService`, `HoldingService`, `StockGroupService`, `PortfolioSummaryService` — Holdings persistence reads `ReplayResult.terminalByMaster()` (no parallel AVCO loop). The shadow-mode flag and legacy paths were removed once parity burned in (ADR-018, ADR-024).
- **Session-Scoped View Toggles, Not Profile Writes** — global UI context modifiers (notably the reporting-currency dropdown) live in session-only Angular Signals (`NavbarStateService`). Two seed sources, both gated by a single `sessionOverridden` flag that flips true on any user dropdown click: `seedFromUserIfUntouched(profileCurrency)` (called from `AppComponent` on `currentUser$` emit and on every `NavigationEnd`, but **skipped on `/portfolio` routes**) and `seedFromPortfolioIfUntouched(portfolioCurrency)` (called from `PortfolioComponent.loadPortfolios` when exactly one portfolio is in context, with a fallback to the user-profile seed for multi-portfolio mode). The portfolio-route guard prevents an EUR-then-INR flicker for users whose profile currency differs from their broker portfolio's native currency. After seeding, `PortfolioComponent.reportingCurrency` is read back from the signal **synchronously** before `loadHoldingsForPortfolios` fires so the holdings HTTP request and the constructor-effect-driven `onReportingCurrencyChange` cannot race on different currencies. Seeds MUST NOT call `PUT /api/users` or write to `localStorage` — profile-level currency changes publish `ReportingCurrencyChangedEvent` and force a full `normalized_reporting_*` rebuild across the user's ledger, which is correct for a Settings action and catastrophic for a header toggle. Backend endpoints respect the signal via an optional `?reportingCurrency=XXX` param with a profile fallback (ADR-016).
- **Holdings Authority Is Three-Way (SnapTrade Snapshot, Cutoff-Anchored Converted, Pure Replay)** — no HTTP endpoint creates or deletes a `holdings` row directly (`PUT /api/holdings/{id}` patches metadata only; superuser `POST /api/v1/admin/holdings/{id}/rebind` swaps same-master `acquired_listing_id` per ADR-045). `HoldingService.updateHoldingsForPortfolio` and `updateHoldingForMaster` branch by portfolio provenance: (1) **SnapTrade-linked (`SnaptradeConnectionRepository.existsByPortfolioId`)** — `SnapTradeHoldingsReconciler` owns `holdings`; replay rebuilds emit `UserHoldingsChangedEvent` and return early without touching rows, and `POST /api/holdings/rebuild` + `POST /api/mutual-funds/sips` return `409 Conflict`; (2) **Converted to Manual (`converted_from_broker_sync_at != null`, ADR-050)** — broker-anchored masters project `broker_snapshot_quantity * postCutoffSplits + (replayAll - replayPreCutoff)` at the UTC `LocalDate` cutoff so unledgered/oversold pre-conversion positions survive rebuilds and backdated fixes close the gap without inflating share counts; (3) **Pure Manual / CSV (`converted_from_broker_sync_at == null`)** — `holdings` is a strict projection of `ReplayResult.terminalByMaster()`, with unbacked orphan pruning routed through `OrphanHoldingPrunePolicy` (`prune_orphan_manual_holdings` flag, default `false` dry-run). Oversold replay qty is never clamped and surfaces via `ReviewState.OVERSOLD` with split-normalized peak shortfall `S(d0) * max_k(-q_k / S_k)` above `QTY_COVERAGE_TOLERANCE` (`0.0001`) (ADR-020, ADR-024, ADR-031, ADR-045, ADR-050).
- **Corporate-Action Listeners Recompute One Master, Not the Whole Portfolio** — `HoldingsRecomputeOnCorporateActionListener` (and any future `@TransactionalEventListener` consuming `MasterCorporateActionsRefreshedEvent`) routes through `HoldingService.updateHoldingForMaster(portfolioId, masterId)` — never `updateHoldingsForPortfolio`. The per-master path still replays the full ledger (cost basis is FIFO/AVCO-dependent across the portfolio) but persists exactly one Holding row, so a single JIT-seeded split cannot cascade into a portfolio-wide rewrite that resurrects skeleton Holdings for every master in the ledger. The portfolio-wide method is reserved for callers that intentionally rebuild every position (CSV import commit, `POST /api/holdings/rebuild`). `persistHoldingFromReplay` backfills `Holding.broker_raw_ticker` from the acquired listing's ticker only when currently NULL — the "never overwritten" rule on broker-specific suffixes (e.g. `RELIANCE-EQ`) is preserved (ADR-039).
- **Server-Classified Holdings Triage & Bidirectional Position Reconciliation** — `PortfolioReviewClassifier` (`core`, routed via ADR-037 `PositionGapReconciliationStrategy` on `snaptrade_position_reconciliation` with once-per-portfolio-per-UTC-day shadow logging) unifies `LedgerGapDetector` with position-vs-ledger comparison across `HoldingService`, `HistoryQueryService`, and holding-only `SecurityMasterAliasService.linkAlias` counterparty verification (supporting both 1:1 split-equivalent pairs and same-portfolio unequal-quantity holding/disposal pairs), emitting `ReviewState` (`OK | OVERSOLD | MISSING_BUY_HISTORY | UNRECORDED_DISPOSAL | ORPHANED_BUY_NEEDS_RENAME | MISSING_LOCAL_EVENT | MISSING_GLOBAL_RENAME`) and `ReviewActionHint` (`suggestedQuantity`, `suggestedTransactionDate` — left `null` for untracked `MISSING_BUY_HISTORY`/`UNRECORDED_DISPOSAL` so users pick the actual trade/gift date — `suggestedCounterpartyMasterId`, `renameConfidence`). Live SnapTrade reconciliation requires settled connections/accounts (`lastSyncedAt != null`, blocking positions-only accounts) plus `portfolio_position_change` grace (`>= 7d` & `>= 2` clean portfolio-wide syncs, `BROKER_SYNCED`-only `< 7d` txn suppression), defers all merger/spin-off DAG descendants while any ancestor is open, grades 1:1 split-equivalent rename pairs `HIGH` (corroborated → primary `Link`) vs `LOW` (quantity-only → secondary), and vetoes partial-sell + unrecorded-disposal terminal cliffs in `PortfolioLedgerCoverageEvaluator` (`LedgerCoveragePolicy`). On the frontend, `-RE` tickers keep `Mark as rights allotment` primary, normal `OVERSOLD`/`MISSING_BUY_HISTORY` rows promote `Add missing BUY / Gift` (demoting `Mark as free entitlement` into `…` overflow with warning), `> 10` missing-buy rows collapse into a summary card, and `AddBuyDialogComponent` supports `BUY`/`SELL` modes with scalar `historical-close` auto-fill (including async cold-cache Yahoo warmup polling + `.BO` → `.NS` fallback for stubbed BSE listings) and pre-split `[Apply N]` banners (ADR-024, ADR-032, ADR-034, ADR-051).
- **AI-Assisted Mapper Pattern** — LLM involvement in CSV import is limited to schema inference: header + 5 sample rows in, `MappingProposal` JSON out. Java parses the full file deterministically via Apache Commons CSV using the user-confirmed mapping. The LLM never touches numeric values, dates, or the commit path. Every non-null column name in the proposal is validated against the real header server-side before use (injection defence). One LLM call per import regardless of file size. The mapping schema extends to heterogeneous broker formats (Freetrade, Trading 212, …) via four optional `ColumnMapping` fields — `directionColumn`, `dividendPriceColumn`, `skipTypes`, `typeAliases` — that the LLM populates and the user never edits (ghost state). `RowStatus` resolves to one of `NEW | DUPLICATE | SKIPPED | INVALID | CASH_FLOW | CORPORATE_ACTION_DROPPED`: cash events route to `cash_flows`, broker corp-action labels are dropped at ingest (canonical source is `corporate_action_*` per ADR-029), genuinely-unrecognised rows stay `SKIPPED` for visibility, and the preview surfaces a "show skipped categories" expander so the user can reclassify a category back to a trade type and re-run preview. `AiCsvMapper` pre-seeds corporate-action broker labels into the LLM-supplied `skipTypes` so they appear auto-handled from the first preview round-trip. A multi-modal file positively recognised by a deterministic broker interpreter bypasses this LLM path entirely (next bullet) (ADR-020, ADR-026, ADR-029, ADR-047).
- **Deterministic Broker CSV Interpreters Pre-empt the LLM Mapper** — a multi-modal broker file (one whose canonical fields aren't a plain per-column read — e.g. Questrade "Activities", where the `Action` column interleaves row schemas) is parsed by a `CsvRowInterpreter` (`core`) that positively recognises it via header-set match (`headers.containsAll(SIGNATURE)`, robust to reorder/append). `CsvImportService.preview()` and `AiCsvMapper.inferMapping()` consult `CsvInterpreterRegistry` **before** the ADR-020 LLM mapper, which is then bypassed (`MappingProposal.deterministicInterpreter` carries the format name; frontend shows a "recognised format" banner and skips column-confirm). `interpret(CsvRow)` returns a neutral `ParsedActivity` (`TRADE | DIVIDEND | CASH_FLOW | CORP_ACTION_DROP | SKIP`) mapped to the existing `PreviewRow` reusing the shared date/dedup-hash/validation/`buildCashFlowRow` helpers, so **`commit()` is unchanged**. `QuestradeRowInterpreter` routes by `Action` (signed-qty sells → magnitude, `DIV` share-count parsed from `Description`, cash events via `BrokerActivityClassifier`, `DIS … STK SPLIT` dropped, journals skipped) and **owns two broker-specific decisions that must stay interpreter-local, never in the shared `ParsedActivity` model / LLM mapper / `SecurityListingService`**: (1) **exchange inference** — `CAD`/`.TO` → `TSX`, `USD` → `NYSE` (routing hint into EODHD's single `.US` feed), `.TO` stripped from the ticker (FIGI resolves `RY`; EODHD re-derives `RY.TO`; twin `RY`/`RY.TO` forms collapse to one listing), carried on `ParsedActivity.exchange()` so the listing mints *with* an exchange and prices instead of degrading to an ambiguous ticker-only OpenFIGI lookup — sound only because Questrade is single-country (the ADR-027 FIGI writeback only fires on a *null* exchange, so this is never clobbered); (2) **instrument classification by Description** (never symbol — Questrade hides these behind internal ids) — options (`CALL `/`PUT `) and GIC/term-deposits (`GIC` or `MAT <date> <rate>%`) `SKIP` rather than minting $0-valued positions, while genuine GIC `INTEREST` still books to `cash_flows` and internal-id real securities (`A603109` = an Apple dividend) are kept-unpriced (the dividend still counts; the listing self-heals out of the backfill banner). Bounds: one class + one golden test per broker, no persisted config / JSONB / LLM-chosen value logic; the registry is empty for columnar brokers, so their LLM path is byte-for-byte unchanged (ADR-047, amends ADR-026; extends ADR-020).
- **CSV Dedup is Strict — No Ordinal Fallback (`csv:v2:`)** — the row dedup hash (`externalId`) is keyed on `portfolioId | ticker | isoTimestamp(UTC) | type | qty | price | currency | externalTradeId`. Two rows that hash identically are duplicates; no row-ordinal suffix is ever appended to invent uniqueness. Partial fills from broker tradebooks (e.g. Zerodha `trade_id`) require the user to explicitly map the `externalTradeIdColumn` — silent position inflation via fabricated uniqueness violates the Accuracy principle. Re-upload of any file is always idempotent. Timestamp parsing treats naive `LocalDateTime` strings as UTC verbatim (no regional zone conversion), so the trade date never shifts across the midnight boundary (ADR-021).
- **Bare-CSV Listing Resolution — Broker Alias, FIGI Writeback, Manual Override** — broker-supplied exchange descriptions ("London Stock Exchange", "Knight Equity Markets LP") and broker-form tickers (Trading 212's `BMWD` → canonical `BMW3`) are normalised at ingest by `BrokerExchangeAliasResolver` / `BrokerTickerAliasResolver` (hardcoded `core` maps). Listings that still land with `exchange_id = NULL` (ticker+currency-only CSVs) hit OpenFIGI ticker-only; `FigiResolutionService` persists the resolved Bloomberg `exchCode` to `figi_resolution_stage.resolved_exch_code` and reverse-maps it via `BLOOMBERG_TO_EXCHANGE_CODE` to back-fill `listing.exchange_id`, then triggers `JitSecuritySetupService.onNewListingCreated` so EODHD price backfill can run. The `GR → XETRA` reverse-map tie-break is documented and known-imperfect for Berlin-only / Frankfurt-floor-only securities; the manual override endpoint `PATCH /api/figi-resolution/listing/{id}/exchange` (admin-token-gated) and the bulk repair endpoint `POST /api/figi-resolution/repair-unresolved` close the residual gaps. Ticker-only matches use a separate `TICKER_CONFIDENCE_THRESHOLD = 0.30` (ISIN-based stays at `0.90`) since validation already hard-rejects currency mismatches (ADR-027).
- **Backfill Progress is Hybrid — Derived for In-Progress, Persisted for Terminal** — async historical-price backfill jobs (`EodhdHistoricalPriceBackfillJob`, `CorporateActionSplitBackfillJob`) hold no progress state on a portfolio-level row. The CSV path's `GET /api/v1/csv-import/backfill-status` and the per-portfolio path's `GET /api/v1/portfolio-sync-status` derive `{status, syncPhase, completedCount, totalCount, pendingListingIds}` from `market_data_price_daily` over the user's owned listings, with three pending-set filters: FAILED `ticker_resolution_queue` entries (joined via `holdings.acquired_listing_id`), `market_data_symbol.backfill_status IN ('FAILED', 'NO_DATA')` — the per-symbol terminal verdict written by the JIT job on every retry-exhaustion / non-retryable / empty-bars-no-prior-data exit, clearing within one poll cycle (ADR-041) — and stale `MarketDataSymbol` rows whose `created_at` is older than **15 minutes**. The 15-min staleness window stays as a backstop for the path where the job dies before writing terminal status (process crash, executor queue overflow); it is no longer the primary clearing mechanism. The frontend renders at most one banner at a time with precedence SnapTrade > CSV > Prices; the SnapTrade "All data synced!" success copy is suppressed while prices are still SYNCING. The prices banner persists its poll start timestamp to `sessionStorage` so the 10-min stuck-state and 30-min hard-cap thresholds cannot be reset by reloading. No per-portfolio `*_backfill_status` table, no SSE/WS, no `BACKFILLING_PRICES` lifecycle on `SnaptradeConnection.sync_phase` (ADR-022, ADR-028, ADR-041).
- **Portfolio Last-Synced Read Path — Connection Wall-Clock, Not the Cursor** — `GET /api/portfolios` exposes `PortfolioDto.lastSyncedAt` sourced from `snaptrade_connection.last_synced_at` (wall-clock, set to `now()` on every successful sync), **never** `portfolios.last_synced_at` (the `toDate+1` incremental recent-sync cursor, which is future-dated and would render as "synced tomorrow"). `SnaptradeConnectionRepository.findLastSyncedAtByUserId` returns `MAX(last_synced_at)` GROUP BY `portfolio_id` because no unique constraint guards one-connection-per-portfolio — a plain projection 500s the list endpoint via `Collectors.toMap` duplicate keys for reconnected portfolios. Non-linked portfolios resolve to `null` → "Not synced yet", sync button disabled. Frontend `SyncControlComponent` (projected into `PageHeadingComponent` via `<ng-content>`) shows the oldest selected portfolio's time with a per-portfolio hover breakdown; `syncAllPortfolios()` filters to `isLinked` targets (ADR-046).
- **Never Drop Data** — SnapTrade ingestion persists first (raw JSONB + `broker_raw_ticker`) and resolves asynchronously. Holdings are usable before pricing resolves.
- **Closed-Loop Broker Selection** — the frontend can never display, and the backend will never link to, a broker absent from `broker_metadata`. `GET /api/brokers` filters server-side to active rows with non-null `snaptrade_slug`; `POST /api/brokers/snaptrade/connect/start` accepts `brokerId: Integer` only, and `SnapTradeService.start` resolves the slug from `BrokerService.getBrokerById` before forwarding `.broker(slug)` to the SnapTrade SDK. Slugs are case- and punctuation-sensitive on the wire — the DB stores them in canonical SnapTrade form, sourced via the superuser endpoint `GET /api/v1/admin/snaptrade/brokerages` (wraps `referenceData.listAllBrokerages`). Failure routing is structured (`SnaptradeConnection.failure_reason` enum); the frontend `@switch`-renders on it and never pattern-matches `lastSyncError` text. `UnsupportedBrokerException` is the safety net for API tampering / deactivation races, not a user-visible flow. The Redis-backed `brokers` cache clears on every startup via `BrokerCacheStartupClearRunner` so any seed-fix migration is correct on next deploy without operator intervention (ADR-030).
- **SnapTrade Activity Routes to Three Destinations, Polymorphically** — every `broker_activity_log` row lands in exactly one of `transactions` (trades + per-account corp-action receipts; `parsed_entity_type='TRANSACTION'`), `cash_flows` (non-trade cash with no security listing; `parsed_entity_type='CASH_FLOW'`), or stays `UNMAPPED_TYPE` for operator triage. The `corporate_action_*` tables are populated by EODHD/BhavKosh jobs and admin endpoints only — SnapTrade Activity never writes to them. `MERGER` direction is resolved by sign-of-quantity; null/zero stays UNMAPPED. `OPTION_*` types stay UNMAPPED (no AVCO treatment yet). Adding a new activity type is a routing decision: trade-shaped with AVCO impact → `transactions`; pure cash → `cash_flows`; otherwise UNMAPPED. New `Transaction.TransactionType` values require corresponding `RealizedGainCalculator.applyTransaction` math + CSV alias coverage — otherwise prefer `cash_flows`. Synthetic external_ids never leave `broker_activity_log`. `SnapTradeActivityMapper` (extracted in D3) owns the switch (ADR-028).
- **System-Identity Vendor Tokens — Singleton Row, Superuser-Captured, Server-Side Exchange** — credentials that authenticate the application (not the user) live in a dedicated single-row table per vendor, keyed by a fixed UUID, with sensitive fields encrypted via `EncryptedStringConverter`. The OAuth-style code grant runs through a class-level `@PreAuthorize("hasRole('SUPERUSER')")` admin controller that exchanges the auth code via `RestClient` server-side using the secret stored only in `application.properties` — the frontend supplies only the public `client_id` and a runtime-derived `redirect_uri`, never the secret. Status endpoints return `{present, expiresAt, refreshedAt, expired}` and **never** include the token. The frontend `superuserGuard` is UX only; the `@PreAuthorize` is the security boundary. Admin surfaces sit under `/admin/...`, not `/settings/...` (the initial Fyers V3 instance was retired in ADR-049; the pattern remains canonical for future system-identity vendors) (ADR-036, ADR-049).
- **Feature Flagging — Guard at the Perimeter, Branch by Abstraction** — flags gate features at the **entry point only**. New endpoint / new route / new top-level UI surface: throw `ResponseStatusException(NOT_FOUND)` in the controller (backend) or short-circuit via a `CanActivate` route guard / single top-level `@if (featureFlags.isEnabled(...))` (frontend). Inline `if (enabled)` checks deep in services, calculators, or shared templates are forbidden — they make the legacy path uncleanable. Behavior-changing flags use Strategy + factory: extract the affected logic to an interface, keep the current code as `Legacy{Name}Impl`, add `V2{Name}Impl`, and choose between them in a `@Configuration` `@Bean` factory (backend) or a `useFactory` provider in `app.config.ts` (frontend) that consults `FeatureFlagService.isEnabled(...)` at injection time. Spring's `@ConditionalOnProperty` is not viable — flags are runtime-mutable in Postgres/Redis, not startup-time. **Fail closed by contract:** `FeatureFlagService.isEnabled(key)` returns `false` for unknown keys, cache misses, and DB/Redis outages — never override with permissive defaults. Flag state lives in the `feature_flag` table (per-env DB, naturally environment-scoped), Redis-cached under `featureFlags` (5-min TTL, evicted on every admin write). Admin UI at `/admin/feature-flags` is superuser-gated; the "Days Active" column is the retirement signal — a flag on in prod past its rollout window is tech debt and the abstraction must be collapsed (delete `Legacy*`, rename `V2*` to canonical, drop the row). Public `GET /api/v1/features` returns only the enabled-key list to avoid leaking disabled flag names (ADR-037).
- **Money = `BigDecimal`, Time = `Instant`/`OffsetDateTime` (UTC)** — never `double`/`float`/`Date`/`LocalDateTime`.
- **FX Fallback Hierarchy (in order):** broker FX → local historical FX (`fx_rate` table) → live FX snapshot. Missing rate degrades gracefully, never breaks the UI.
- **All-or-Nothing USD Normalization** — the USD-normalized cost basis path activates only when BUY transaction quantity ≥ held quantity. Otherwise fall back to live FX. No blending.
- **No Sync External Calls on Hot Path** — EODHD/OpenFIGI/Yahoo/BhavKosh/AMFI only in scheduled jobs, async executors, or admin endpoints. Reads serve from DB/Redis.
- **Chunked Async Backfills** — event-driven (`@TransactionalEventListener(AFTER_COMMIT) @Async`), batched (100 rows), DB-only inside the loop.
- **Async Corporate-Action Backfill Iteration Uses Flat Projections Only** — `CorporateAction{Split,Dividend,Spinoff}BackfillJob` sweep + JIT paths iterate `MarketDataSymbolRepository`'s flat-projection views (`ActiveBhavKoshSymbolWithMasterView`, `ActiveEodhdSymbolWithMasterView`) and never `JpaRepository<SecurityListing,...>` / `JpaRepository<SecurityMaster,...>` methods that return entities with lazy `exchange` / `security` associations. Counterparty resolution by ticker (DEMERGER `toSymbol`, future MERGER targets) uses `SecurityListingRepository.findIndianListingsByTickerWithMaster` — also a flat projection. The `@Async("backgroundJobExecutor")` thread has no Hibernate session; helpers like `findById`, `findFirstBySecurityAndIsPrimaryTrue`, and `findAllByTickerIgnoreCase` return entities whose next `.getExchange()` / `.getSecurity()` access throws `LazyInitializationException`. The Split/Dividend/Merger admin paths (`backfillForSecurity(UUID)`) still call `resolveIndianListing(master)` and are the documented residual violation, tracked as follow-up (ADR-043).
- **Postgres-as-Queue** — `SELECT FOR UPDATE SKIP LOCKED` for FIGI/ticker resolution pollers; no Kafka/RabbitMQ.
- **Module Boundaries Enforced** — `core` = domain only; `api` = HTTP/security; `jobs` = headless scheduled work. `jobs` never imports `api`.
- **LLM Ingestion** — normalize currencies (to reporting currency) before any LLM input.
- **Aggregation Key is Always `security_master_id`** — never listing or symbol; cross-exchange holdings must consolidate.
- **Structured Symbol Classification & Indian Ticker Normalization** — `SymbolKindClassifier` (`core/util`) classifies `market_data_symbol.symbol_kind` at every write site (`BhavKoshSymbolDerivationService`, `SnapTradeSymbolExtractor`, `EodhdSymbolMappingJob`, `ZerodhaSymbolMappingJob`, `PriceService` JIT, `HistoricalPricePrefillJob`, `TickerMappingApplier`) so polling queries filter `COALESCE(mds.symbol_kind, 'EQUITY') <> 'RIGHTS_ENTITLEMENT'` without SQL string heuristics. `IndianTickerNormalizer` strips broker series suffixes (`-BZ/-BE/-T/-...`) at SnapTrade ingest, scoped to NSE/BSE only with `-RE` deliberately preserved (ADR-032 dependency); raw broker ticker survives on `holdings.broker_raw_ticker` (ADR-040, ADR-049).
- **Yahoo Quotes Runtime Failure Classification — Tri-State, Fail-Open Negative Cache** — `YahooFinanceClient` classifies responses into `FOUND`, `REJECTED` (explicit upstream `404` / symbol error / empty spark series inside a `200` response), and `FAILED` (HTTP `429`/`5xx`, timeouts, transport errors). Only `REJECTED` symbols are negative-cached for 24h in `YahooSymbolNegativeCache` (`market_data:yahoo:invalid:<symbol>`, backed by Redis with fail-open fallback to a bounded in-memory map on `DataAccessException`, and auto-cleared on positive quotes) so transient network or rate-limit blips never suppress valid tickers (ADR-042, ADR-049).
- **Subscription Tiers, `SnaptradeUser` COGS Lifecycle & Zero-Data-Loss Manual Conversion** — `FREE` and expired `EARLY_ACCESS_TRIAL` users get unlimited Manual & CSV portfolios and `0` live broker links; active `EARLY_ACCESS_TRIAL` (90d) and `PRO` users get unlimited live broker links in UX bounded server-side by `snaptrade.max-connections-per-user=20`. `SnapTradeService.start` enforces `SubscriptionTierLimitException` (`403`) **before** `createSnaptradeUser` runs (and re-checks under `UserRepository.findByIdForUpdate` in `persistPendingConnection` / `prepareComplete` / `prepareRetry`, excluding pre-OAuth `brokerage='PENDING'` drafts). Whenever a user drops to `0` `snaptrade_connection` rows, `disconnectConnection` calls `SnapTradeClient.deleteSnapTradeUser` outside `@Transactional` and deletes `snaptrade_user` on 2xx/404, retaining the row on 5xx for `AbandonedConnectionReaperJob` (`02:00 UTC`) retry via `SnapTradeLifecycleRunner` (`core` SPI). Linked-to-manual conversion (`POST /api/portfolios/{id}/convert-to-manual` + `TrialExpiryDowngradeJob` at `02:15 UTC` before `02:30 UTC` `BrokerSyncScheduler`) revokes SnapTrade authorizations, keeps `Portfolio` + `Transaction` + `CashFlow` + `Holding` intact, sets `broker = 99`, strips `snaptradeConnectionId`/`connectionId`/`accountIds`/`accounts` from `broker_metadata`, stamps `portfolios.converted_from_broker_sync_at` from `MAX(snaptrade_connection.last_synced_at)` (fallbacks: `AccountSyncState.lastSyncedAt` → `MAX(BROKER_SYNCED transaction_date)`), and skips only CSV rows inside the bounded SnapTrade-synced window `[earliestBrokerSyncedDate, cutoffLocalDate]` (UTC `LocalDate` per ADR-021, scoped across trades, dividends, and cash flows) in `CsvImportService.preview()` and `commit()` so earlier-year pre-SnapTrade CSVs and post-conversion CSVs import cleanly without duplicating synced history (ADR-050).

## 5. UI/UX Identity & Styling

- **Full-bleed workspace canvases** — dashboards/holdings use the full viewport width; no framing gutters.
- **Tabular-nums for all financial data** — monetary/percentage values use `font-variant-numeric: tabular-nums` and are **right-aligned**.
- **Strict contrast floors** — primary text never lighter than `text-gray-500`; secondary-line reporting-currency rows use smaller, muted weight but stay readable.
- **Stacked multi-currency cells** — native-currency value as primary line, reporting-currency beneath (smaller/lighter). Secondary line hidden when `holding.currency === reportingCurrency` (zero-noise rule).
- **Progressive FX disclosure** — ⓘ icon in Gain/Loss cell, tooltip shows asset return vs. FX impact. Inline cost is zero.
- **Gain/Loss column is reporting-currency only** — enforces tie-out with summary header.
- **Modern Angular control flow only** — `@if`/`@for`/`@switch`; OnPush everywhere; Signals for state, `async` pipe in templates.
- **ECharts for data viz** — declarative `EChartsOption` via Signal; pad-angle donuts, border-radius, emphasis animations. No Chart.js.
- **BEM-inspired SCSS** with design tokens; no repeated raw hex. Use the frontend-design plugin for premium design work (DESIGN.md is deprecated).
- **Hybrid zero-states** — search surfaces preserve the affordance *and* inject actionable live data (e.g., Portfolio Movers) instead of empty icons.

## 6. Security & Boundary Constraints

- **Never log PII** — user emails, broker credentials, raw transaction payloads stay out of logs.
- **Sensitive fields AES-256 encrypted** via `SecretEncryptionService` (SnapTrade OAuth creds, API tokens).
- **JWT bearer on every request** — frontend `AuthInterceptor` injects; `authGuard` protects routes.
- **Single-origin deployment** — Caddy path-routes `/api/*` → backend, `/*` → frontend. No CORS; no third-party cookie domains.
- **Container network isolation** — Postgres/Redis/backend/frontend are reachable only on `app-network` behind `cloudflared` (with `postgres` loopback-bound on `127.0.0.1:5432` for SSH admin access).
- **Never share Postgres credentials beyond the compose network** — only `backend` connects to PostgreSQL in steady state.
- **SnapTrade lookups use slugs**, not user-visible identifiers; account IDs stored as JSONB on the connection, not leaked to the client.
- **No client-side financial aggregation** — totals, realized gain, FX conversion, and tie-out math are always server-computed. The frontend renders server-authoritative DTOs.
- **Admin endpoints (FX backfill, reporting-currency rebuild, vendor-token capture, same-master holding rebind, `broker_exchange_code_map` cache refresh) are superuser-gated** and bounded (e.g., 365-day max per historical-FX call). System-identity vendor tokens are captured exclusively via `POST /api/v1/admin/<vendor>/exchange` and stored as encrypted singletons; the response carries metadata only (ADR-036).
- **Flyway owns schema** — Hibernate runs in `validate`; no runtime DDL. Migrations are idempotent (`IF NOT EXISTS`, `ON CONFLICT`) and backward-compatible.
- **No secrets in repo or chat** — credentials come from environment variables via Spring configuration.
